# AssureLoop Technical FAQ

## Is AssureLoop An OS?

No. AssureLoop is not an operating system and does not replace Zephyr. It is
release assurance tooling around Zephyr-based embedded firmware builds.

## Is It Production OTA?

No. AssureLoop does not provide production OTA transport. It is not production OTA,
not production secure boot, and not a device fleet update service. The current
update workflows are local, simulator-first, and hardware-alpha validation paths
for package verification, MCUboot behavior, and lifecycle evidence.

## Is It Certified?

No. AssureLoop is not certified safety compliance, not certified cybersecurity
compliance, and not a certification package. It can help organize evidence, but
certification claims require exact-scope assessment and independent evidence.

## Why Zephyr?

Zephyr gives AssureLoop a modern embedded firmware baseline with a reproducible
build workflow, west project management, QEMU simulator support, board support,
Kconfig, devicetree, SPDX/SBOM tooling, and MCUboot integration points.

## Why MCUboot?

MCUboot is a widely used open-source bootloader for microcontrollers. AssureLoop
uses MCUboot-compatible signed image workflows because they provide a practical
foundation for signed image artifacts, boot verification investigation, update
staging, confirm behavior, rollback behavior, and negative-update evidence.

The current use is development and hardware-alpha validation. It is not a
production secure boot certification claim.

## What Is SBOM?

SBOM means Software Bill of Materials. In AssureLoop, SBOM output records
software components and source inputs associated with a firmware build. The
firmware evidence workflow can collect Zephyr SPDX files generated by
`west spdx` and include them in the release manifest and evidence bundle.

## What Is An Evidence Bundle?

An evidence bundle is a release artifact directory or archive containing the
release manifest, trace report, referenced firmware artifacts, SBOM files when
available, and supporting evidence files. AssureLoop includes a verifier that
checks the bundle as a complete artifact, including schema validation, artifact
existence, and SHA256 hashes.

## What Hardware Is Supported?

The current hardware-alpha board is ST NUCLEO-H563ZI with Zephyr target
`nucleo_h563zi`. Broad board support is not claimed yet.

The simulator-first reference target remains `qemu_cortex_m3`.

## What Is Simulator-Only Vs Hardware-Proven?

Simulator-first coverage currently includes:

- `qemu_cortex_m3` firmware build and run,
- release manifest generation and validation,
- evidence bundle verification,
- SBOM inclusion,
- update package verification,
- local OTA lifecycle simulation,
- signed image workflow where Zephyr tooling supports it.

Hardware-proven coverage currently includes ST NUCLEO-H563ZI bring-up,
board-specific signed image evidence, MCUboot bootloader chainload, confirmed
update behavior, rollback behavior, tampered secondary image rejection, and
lower-version secondary image rejection for the documented local direct-flash
hardware-alpha path.

Still not claimed: production OTA, production secure boot, cloud update service,
broad board support, or certified safety/cybersecurity compliance.
