# AssureLoop architecture

## Scope

AssureLoop v0.1 is a release assurance platform for a Zephyr-based embedded controller demo.

It has four layers:

```text
┌──────────────────────────────────────────────────────────┐
│ Evidence layer                                           │
│ requirements, tests, trace reports, security checklist   │
├──────────────────────────────────────────────────────────┤
│ Release layer                                            │
│ manifest, signatures, artifact hashes, provenance        │
├──────────────────────────────────────────────────────────┤
│ Firmware platform layer                                  │
│ Zephyr app, telemetry hooks, boot/update integration     │
├──────────────────────────────────────────────────────────┤
│ Hardware/board layer                                     │
│ qemu_cortex_m3 first; industrial MCU profile later       │
└──────────────────────────────────────────────────────────┘
```

## v0.1 design choice

The first target is a buildable controller-style Zephyr application plus host-side release tooling. Secure boot and field OTA are treated as first-class architecture requirements, but v0.1 starts by making the release artifacts and telemetry shape real.

## Main components

### Firmware app

The app lives in `firmware/app` and emits structured logs for:

- boot identity,
- release version,
- build profile,
- control-loop period,
- per-iteration jitter,
- loop summary.

The first build target is `qemu_cortex_m3` because it lets the founder and CI test without hardware. A real STM32H7 or i.MX RT target should be added only after the workflow is proven.

### Release manifest

`tools/generate_release_manifest.py` records:

- product,
- version,
- target,
- build profile,
- git commit,
- dirty-state hint,
- artifact paths,
- artifact sizes,
- SHA-256 hashes,
- SBOM file references when available.

### Signing

`tools/sign_release.py` signs the exact manifest file using OpenSSL. The starter implementation uses RSA dev keys generated by `scripts/create_dev_keys.sh`. Production signing will need a hardware-backed or CI-protected signing policy.

### Verification

`tools/verify_release.py` verifies artifact hashes and optionally verifies the manifest signature.

### Evidence bundle

`tools/build_evidence_bundle.py` collects the manifest, trace report, requirements, test matrix, and security checklist into a reviewable directory and compressed archive.

## Near-term architecture decisions

1. Zephyr is the first RTOS base.
2. Apache-2.0 is the project license.
3. The open-source core includes the firmware demo and core release tooling.
4. Certification claims are explicitly out of scope until exact evidence exists.
5. Board support is intentionally constrained.
